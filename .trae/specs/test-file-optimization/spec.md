# 测试文件系统性优化 - 产品需求文档

## 概述
- **Summary**: 对项目测试文件进行系统性优化，包括清理冗余文件、重构测试结构、验证照片上传功能、集成OCR图文识别、实现RAG业务流程、确保数据库兼容性，并编写详细测试用例。
- **Purpose**: 解决测试代码库的冗余问题，优化测试组织结构，完善照片上传、OCR识别、RAG业务流程的测试覆盖，确保系统功能的正确性和稳定性。
- **Target Users**: 开发团队、测试团队、系统维护人员

## Goals
- 全面清理冗余、无用及重复的测试文件，确保测试代码库的简洁性与高效性
- 对功能相近或关联的测试文件进行合并重构，优化测试文件组织结构
- 验证并确保测试环境中照片上传功能的正确性与稳定性
- 集成OCR模型实现图文提取识别功能，确保能够准确识别图片中的文本信息
- 实现基于检索增强生成(RAG)的完整业务流程测试
- 确保整个业务流程中的所有数据处理环节严格兼容数据库表结构模型
- 为优化后的测试文件编写详细的测试用例

## Non-Goals (Out of Scope)
- 修改生产环境的核心业务逻辑代码
- 重构数据库表结构（仅确保测试与现有结构兼容）
- 替换现有OCR或RAG模型（仅集成和测试现有模型）
- 修改前端代码（仅优化测试文件）

## Background & Context
项目现有测试文件分布在三个主要位置：
1. visual_model/tests - 后端API测试
2. PaddleOCRRAG/tests - RAG服务测试
3. fronted/front/src/tests - 前端测试
4. tests/ - 集成测试

发现的问题：
- 存在多个相似和重复的测试文件（如前端有多个API测试版本）
- 测试文件组织结构不够清晰
- 需要完善照片上传、OCR识别和RAG流程的测试覆盖
- 需要确保测试与数据库模型严格兼容

## Functional Requirements
- **FR-1**: 测试文件清理与重构
  - 识别并删除所有冗余、无用及重复的测试文件
  - 对功能相近或关联的测试文件进行合并重构
  - 优化测试文件组织结构，提升可维护性
  
- **FR-2**: 照片上传功能测试验证
  - 验证文件格式验证功能
  - 验证文件大小限制功能
  - 验证上传进度反馈机制
  - 验证错误处理机制
  
- **FR-3**: OCR图文提取识别集成测试
  - 集成PaddleOCR模型进行测试
  - 确保能够准确识别图片中的文本信息
  - 确保结构化处理识别结果
  
- **FR-4**: RAG业务流程实现测试
  - 实现文本信息向量化处理测试
  - 实现高效检索机制测试
  - 实现结果生成测试
  
- **FR-5**: 数据库兼容性验证
  - 确保数据类型匹配
  - 确保遵守字段约束
  - 确保数据完整性校验
  
- **FR-6**: 测试用例编写
  - 为优化后的测试文件编写详细测试用例
  - 验证各功能模块的正确性
  - 验证整体业务流程的顺畅性

## Non-Functional Requirements
- **NFR-1**: 测试执行效率
  - 优化后的测试套件执行时间不增加超过20%
  - 单个测试用例执行时间不超过30秒
  
- **NFR-2**: 测试覆盖率
  - 核心业务功能测试覆盖率达到80%以上
  - 关键路径测试覆盖率达到100%
  
- **NFR-3**: 可维护性
  - 测试代码遵循项目编码规范
  - 测试文件命名清晰规范
  - 测试注释充分且有意义

## Constraints
- **Technical**: 
  - 使用现有的pytest测试框架
  - 使用现有的Tortoise ORM进行数据库操作
  - 使用现有的PaddleOCR进行OCR识别
  - 使用现有的ChromaDB进行向量存储
  
- **Business**: 
  - 不影响现有生产环境功能
  - 保持与现有数据库表结构兼容
  - 开发时间不超过3个工作日

- **Dependencies**: 
  - 依赖现有的测试fixtures (conftest.py)
  - 依赖现有的测试照片集 (testphoto/test/)

## Assumptions
- 现有测试照片集完整可用
- 现有的数据库模型结构稳定
- 现有的OCR和RAG服务可以正常调用
- 测试环境与生产环境数据库结构一致

## Acceptance Criteria

### AC-1: 测试文件清理完成
- **Given**: 现有测试文件完整
- **When**: 完成冗余文件识别和删除
- **Then**: 测试文件库精简30%以上，无重复测试文件
- **Verification**: `programmatic`
- **Notes**: 通过文件数量对比验证

### AC-2: 测试文件组织结构优化
- **Given**: 完成文件清理
- **When**: 完成相关测试文件的合并重构
- **Then**: 测试文件组织结构清晰，功能分组合理
- **Verification**: `human-judgment`
- **Notes**: 检查测试文件的目录结构和命名规范

### AC-3: 照片上传功能测试通过
- **Given**: 测试环境已准备
- **When**: 执行照片上传相关测试
- **Then**: 文件格式验证、大小限制、错误处理均正常工作
- **Verification**: `programmatic`
- **Notes**: 测试包括JPG、PNG等格式，大小边界测试

### AC-4: OCR图文识别测试通过
- **Given**: 测试照片集已准备
- **When**: 执行OCR识别测试
- **Then**: 能够准确识别图片中的文本信息并进行结构化处理
- **Verification**: `programmatic`
- **Notes**: 验证识别准确率和结构化输出格式

### AC-5: RAG业务流程测试通过
- **Given**: 测试数据已向量化
- **When**: 执行RAG流程测试
- **Then**: 向量化处理、检索机制、结果生成均正常工作
- **Verification**: `programmatic`
- **Notes**: 验证检索相关性和结果生成质量

### AC-6: 数据库兼容性验证通过
- **Given**: 数据库模型已定义
- **When**: 执行数据写入和读取测试
- **Then**: 所有数据类型匹配、字段约束遵守、数据完整性保证
- **Verification**: `programmatic`
- **Notes**: 验证数据库操作不违反任何约束

### AC-7: 测试用例编写完成
- **Given**: 测试文件已优化
- **When**: 完成新测试用例编写
- **Then**: 各功能模块和整体业务流程都有详细测试用例
- **Verification**: `human-judgment`
- **Notes**: 检查测试用例的覆盖度和质量

### AC-8: 文档更新完成
- **Given**: 所有优化工作已完成
- **When**: 完成文档更新
- **Then**: 所有.md文档已更新，反映最新的测试文件结构
- **Verification**: `human-judgment`
- **Notes**: 检查README、测试指南等文档
